# ループの型

mini で実運用中の15本の自律ループ（会議タスク同期・コードレビュー・補助金ウォッチ…）から、
**会社名にもvaultパスにも依存しない土台だけ**を抜き出したもの。実際のループの中身
（何を集めて何を判定するか）は現場ごとに書く「実」であって、ここには含まれない。

## 4つの原則（実運用で削られてきたもの）

1. **根拠の引用をLLMに書かせ、Pythonで機械照合する。**（`citation_verify.py`）
   「完了しました」「決まりました」のような重い判定は申告を鵜呑みにしない。
   出典に実在しない引用を書いた判定はその場で棄却する。でっち上げが構造的に通らない。

2. **承認ゲート。** 金銭が発生する・対外的で不可逆・本人にしか出せない一次情報が要る
   操作は、ループ側で実行しない。直前まで用意して人に渡す（→ `bridge-framework/`）。

3. **差分が無ければLLMを呼ばない。** 平常時のコストは0円。「毎回全部読んで毎回聞く」は
   運用が長くなるほど破綻する。`collect_new_items()` が空を返せばそこで終わる。

4. **足す係と消す係を分ける。** 台帳やタスクリストに「追加する」ループと「完了を検知して
   閉じる」ループは別にする。1本に混ぜると、消す側の誤判定が足す側の実績も壊す。

## 中身

- `common.py` — Discord/Slack投稿・claude -pヘッドレス実行（リトライ/コスト記録つき）・
  単一書き手の関所。**VAULTやチャンネルIDは環境変数で渡す**（ハードコードしない）
- `citation_verify.py` — 原則1の実装。単体で使える
- `loop_template.py` — ①収集→②判断→③機械照合→④⑤実行・記録、の骨格。
  コピーして①④を自分のドメインに置き換える

## 使う前に

- `LOOP_VAULT`（vaultを使うなら）・`CLAUDE_BIN`（既定 `/opt/homebrew/bin/claude`）を設定
- Discord/Slackを使うループは `.env` にトークンを置き、`load_config()` で読む
- 複数機で同じ状態ファイルを触るなら `enforce_single_writer()` を呼び出しの先頭に入れる
- モデルIDは時間とともに変わる。`LOOP_MODEL_LIGHT` 等は使う直前に現行のエイリアスで埋める
