# 承認カードの型

Discordボットで「素案を出す→ボタンで承認をもらう→実行する」を実装するときの型。
mini の discord-claude-bridge（会議→段取りループ）から抜き出したパターン。
3482行ある実物そのものは業務カードの種類が多く一体化しているため同梱していない
——ここでは**型だけ**を示す。実装は現場のDiscordライブラリ（discord.py等）に合わせて書く。

## 状態機械

```
素案作成 → 承認待ち → [✅承認 / ✏️直す / ❌却下]
                          │
                          ✅承認
                          ▼
                  bridge-framework/dispatch.py で実行機へキュー投入
                          ▼
                       実行 → 結果をカードに返す
```

- 承認待ち以外の状態（承認済み／却下済み）でボタンを押されたら、**再実行せず**
  「もう処理済みです」とだけ返す（多重実行の防止）。
- ボタンは `custom_id` に「種別:素案ID:動作」を埋め込み、ボット再起動後も
  同じボタンから復元できるようにする（discord.pyなら `DynamicItem` 相当）。
- 押せる人を1人（本人）に絞る。他人が押しても弾く。

## 承認前に外へ出るものは無い

素案は保存先（vault・ローカルファイル）とDiscordに置くだけ。**承認が押されるまで、
送信・投稿・支払い・削除のような対外的操作は一切実行しない。**

## 承認後の実行指示に必ず添える文（3ゲートの徹底）

```
【守ること】
- まず素案ファイルを読む。ゼロから作り直さず、素案を土台に完成させる。
- 成果物は決められた保存先に置く（Desktop・/tmpに置かない）。
- お金が発生する操作、外部への送信・投稿・申請、本人にしか出せない一次情報が
  要る操作は実行しない。直前まで用意して止め、何が必要かを書く。
- 事実を作らない。裏が取れないことは「未確認」と書く。
- 終わったら、何をどこに作ったかを短く報告する。
```

これは実行者（ヘッドレスclaude等）への指示文の一部として毎回渡す。
承認ボタンを押した瞬間に何でも自動実行されるわけではない、という前提を保つための文面。

## 根拠の必須化

素案そのものにも、citation_verify.py と同じ原則を適用する。「この会議でこう決まった」
という素案には、議事録中の根拠一文を必須にし、その一文が実在するかを機械照合してから
Discordへ出す。存在しない根拠の素案は、人の目に触れる前に破棄する。
