# 過去に指摘されたこと（レビュー役に必ず渡す）

実際に差し戻された・指示された内容をここに1行ずつ足していく。**これが品質の蓄積先**。
（最初は、多くの現場で共通する指摘だけが入っている）

## 分かりやすさ
- 文字が多すぎてページが何なのかパッと分からない → **説明を足すより削る**
- 1ページ1メッセージ。見出しだけ読んで流れが分かること
- 関係者が**誰でも**理解できる構成。いきなり詳細に入らず**概要から**
- お金の流れ・分配は**図かグラフで直感的に**
- 各ページで「何を話し、読み手にどういう気持ちになってもらうか」が決まっているか
- 前回からの変更点の説明ではなく、**この資料そのもの**の話を書く
- テスト段階の資料は「課題と打ち手」より「仮説と検証」の言い方
- 企画書・テスト計画には**何の数値を取るか**と、その判断基準を入れる

## 見た目
- **見切れ・画像が小さすぎる・潰れは絶対に出さない**。全ページ機械点検で0件
- 下端に文字が接するのも不可。余白を残す
- 区切り線が太いとダサい。装飾は細く控えめに
- 左右のバランスを取る。並ぶ要素は近しい表記に揃える
- 人物写真は全員の顔が見えるように
- 大きく直したページは前版と比べる
- 相手が後で直す資料では、表とグラフは編集できる機能で作る（絵にしない）

## 事実と数字
- 数字を作らない。一次情報が無いものは★「要確認」で明示し、推測で埋めない
- 誰の発言・誰が出した案かを切り分ける
- 資料ごとに実績の数字が食い違っていないか

## 表記（間違えやすい固有名詞）
- （指摘されたらここに足す。例：◯◯（△△は誤））
- 固有名詞は、該当案件の記憶ファイルに書かれた表記を正とする
