# 汎用型FOX

新しいPC・新しい会社にも同じ種類のエージェントを立てるためのキット。
すでに実運用されているエージェント群から、会社名・案件名に依存しない部分だけを
取り出してテンプレート化したもの。ゼロから設計したものではない。

## はじめての人は → `STEP0.md`

Claude Code すら入っていない素のMacから始めるなら **`STEP0.md`** を先に見る。
このキットは Claude Code を**入れません**（組み立てるだけ）。

読む順番: `STEP0.md`（素のMac → 動く状態）→ `install.sh` 実行 → `BOOTSTRAP.md`（育てる）

## これは何が「汎用」なのか

FOXという**種**そのものは、実はもう複数の場所で動いている。

- 作業機（ノートPC）— 個人・事業と案件を担当
- 常駐機（デスクトップ）— 同じ持ち主・自動化そのものを担当
- 会社用機 — **別の会社・別の名前・別の記憶**で稼働中

3台目は、名前も会社も記憶も別だが、**アーキテクチャは同じ**:
人格宣言1枚（`~/.claude/CLAUDE.md`）＋開いた場所ごとの記憶（`~/.claude/projects/*/memory/`）
＋出力ルール＋保管先ルール。**このキットは、その共通アーキテクチャを取り出して
テンプレート化したもの。** 「3台目を作った手順」を再現可能にした、と言ってもいい。

## 中身

```

  STEP0.md                          ★素のMacから始める人向けの導入手順（Claude Code本体から）
  install.sh                        実行するとこの端末に組み立てる
  claude/
    CLAUDE.md.template               人格宣言のひな形（{{AGENT_NAME}} などを埋める）
    settings.json                    確認ダイアログを減らす既定設定（bypassPermissions等）
    hooks/guard-output-location.py   生成物がDesktop/Downloads/ホーム直下に散らばるのを防ぐ
  memory/
    MEMORY.md.template               記憶の索引スケルトン
  tools/                             会社名・案件名に依存しない汎用ツールだけを選んで同梱
    claude-token/                    認証切れで常駐が黙って止まるのを防ぐ長寿命トークン配布
    fox-git-guard/                   秘密情報をGitHubに上げさせないpre-commitフック
    fox-repo-sync/                   複数機のリポジトリで「取り残し」が無いか洗い出す
    netdiag/                         「繋がらない」の原因をその場で特定するスナップショット
    psi/                             PageSpeed Insights を1コマンドで叩く
    capslock-nosleep/                フタを閉じてもスリープしない常駐（作業機向け）
  loop-framework/                    ★自律ループの型（実運用15本から抽出）
    common.py                        Discord/Slack投稿・claude -pヘッドレス実行(リトライ/コスト記録)
    citation_verify.py               根拠引用の機械照合＝でっち上げを構造で止める仕組み
    loop_template.py                 収集→判断→機械照合→実行→記録、の骨格
  bridge-framework/                  ★機体を跨ぐ実行と承認の型
    dispatch.py                      共有フォルダ経由のジョブキュー（危険パターン自動ブロック付き）
    session_guard.py                 ★headlessボットの安全弁（下の「常駐ボット型の注意点」参照）
    discord_conversational.py        ★会話ボットの既定装備2点（下の「会話の質」参照）
    table2png.py                     表をPNG化（Discord等はMarkdown表を描画しないため）
    GOVERNANCE.md.template           ルーティング方針＋3ゲート（金銭/対外不可逆/一次情報は必ず人に）
    approval-card-pattern.md         「素案→承認ボタン→実行」の状態機械の型
  skills-catalog.md                  ★候補58本のカタログ（発動索引はCLAUDE.md側で現場ごとに育てる）
```

`loop-framework/` と `bridge-framework/` は `install.sh` では自動配置しない
（Discordトークン等、使う前に人の設定が要る実行系のため）。使う現場で `~/Tools/` 等へ
手でコピーし、各READMEに沿って配線する。

## 入っていないもの（意図的）

- **記憶そのもの**（案件名・シートID・取引先名）— 会社が変われば中身も変わるので運べない
- **鍵・トークン**— `~/.config/claude/token` に各自で発行する（BOOTSTRAP.md）
- **ログイン済みブラウザプロファイル**— macOSキーチェーンの鍵で暗号化されていて機械をまたげない
- **業務固有ツール**（現場ごとの会話ボット・センサー・特定顧客向けCLI等）— これらは「エージェントが
  現場で育てた自動化」であって「FOXという種の一部」ではない。汎用型には含めない
- **スキル発動トリガー索引の中身**— 実運用中の端末の索引（18項目）は6ヶ月の実運用ログから拾ったもので、
  新しい現場でそのまま使うと過学習になる。テンプレートは空。**その場で使いながら育てる。**
  候補一覧は `skills-catalog.md`（58本）を見る

## 使い方

```bash
cd ~/Tools/portable-fox
./install.sh --owner "<持ち主の名前>さん" --machine-label "新しいMac" --dry-run   # まず確認
./install.sh --owner "<持ち主の名前>さん" --machine-label "新しいMac"             # 実行
```

主な引数（すべて省略可、`--owner` だけ必須）:

| 引数 | 既定 | 意味 |
|---|---|---|
| `--agent` | `FOX` | 一人称・呼び名。別の会社に入れるなら別名にする |
| `--owner` | — | この端末の持ち主（必須） |
| `--machine-label` | ホスト名 | CLAUDE.md冒頭に出す端末の呼び方 |
| `--role` | 個人の作業機 | この端末の役割 |
| `--vault-path` | 未設定 | ノート・資料の置き場（決まっていれば） |
| `--github-org` | 未設定 | コードの置き先 |
| `--memory-home` | `$HOME` | 記憶を紐づける「開いた場所」。ホーム以外を主戦場にするなら変える |
| `--skip-tools` | — | `tools/` の同梱ツールをコピーしない |

**既存ファイルは上書きしない。** `~/.claude/CLAUDE.md` が既にあれば下書きを別名で置くだけ、
`settings.json` は和集合マージ、記憶は既にあれば触らない。

## 常駐ボット型の注意点（`claude -p` を継ぎ足すなら）

インタラクティブなターミナル/IDEセッション（`settings.json` の `defaultMode: bypassPermissions`
で足りる）と、Discord/Slack等から `claude -p` をヘッドレスで叩く常駐ボットとでは、権限の渡し方が違う。
実運用中の会社用ボットの例では `~/.claude/settings.json` に `defaultMode` を置かず、
呼び出し側のコードで毎回 `claude -p <prompt> --permission-mode bypassPermissions` と
CLIフラグで渡している。`~/.claude/hooks/` も置いていない（出力ガードは対話セッション向けの
仕組みで、ボット側の書き込み先はコード側で決め打ちしているため）。**ボットを書くなら
`session_guard.py` を隣に置いて import すること**（会話肥大化・切替直後の作り話・上限到達時の
無言エラーの3事故を防ぐ、実際に起きた事故から作った部品）。

## この後（人がやること）

`BOOTSTRAP.md` を見る。ログイン・長寿命トークンの発行・CLAUDE.mdの個別ルール書き足しは
自動化していない（対話コマンドが要る／各社の事情そのものだから）。
