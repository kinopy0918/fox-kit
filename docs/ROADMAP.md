# fox-kit ロードマップ

実運用している3台（持ち主の作業機・常駐機・会社AI機）を棚卸しし、fox-kit に入っていない汎用の仕組みを段階に分けたもの（2026-09-27）。

## 0.1（最初の公開版に入れる：安全と土台）

| 項目 | 何をするか | 元 |
|---|---|---|
| 危険操作ブロック | 破壊・外部への流出になるコマンドを実行前に止める（hook） | 常駐機 |
| 秘密 commit ブロック | .env・鍵が add/commit/push に混ざるのを止める（hook） | 常駐機 |
| スキル・MCP の見張り | スキル／プラグイン／hook／MCP の増減を毎日差分で点検。知らない外部MCPは拒否リスト | 常駐機 |
| モデルの固定 | 常駐のブリッジが勝手に軽いモデルに落ちないよう明示 | 作業機 |
| 常駐の健康診断 | 毎朝、常駐ジョブが起動できるか・直近で失敗していないかを点検して知らせる | 常駐機・会社AI機 |
| 会社の規約テンプレ | 保存先・正本は1つ・個人情報は自動で動かさない・迷ったときの判定表／「知らない」と「渡されていない」を言い分ける | 会社AI機 |
| 監査ログ | 誰に・どのチャンネルで答えたか、何を書いたかを #記録 に1行ずつ | 会社AI機 |
| 添付の即時回収の強化 | HEIC→jpg、動画→コマ画像、読めないものは読めないと言う | 会社AI機 |
| ブリッジの安定化 | 長文の分割投稿をまとめる・直近の会話を文脈に入れる・混雑時の再試行・チャンネル単位の排他 | 常駐機 |
| 専用機の追加設定 | 自動ログインの案内・ネットワーク経由で起こす・FileVault の復旧キー確認 | 常駐機・会社AI機 |

## 0.2（秘書の中身）

朝ブリーフィング／メールの仕分け＋返信案の承認送信／表計算・Gmail の読み書き道具／会議→タスク→承認→実行（証拠つきの完了）／会話から決定を✅で拾う／承認ボタン／部署ごとの窓口（ペルソナ・名前とアイコン）／週次バックアップ＋未保存の検知／鍵の配り方（複数台）／自動修復（ログのエラーを拾って直す）／Google の認証手順書

## 0.3（会社に1体のAI）

区画アクセス制御（質問者のロールで開ける資料の範囲を分け、区画ごとに別の読み取り専用の鍵）＋鍵の越境監査／読みは分散・書きは1系統に集約（追記のみ）／サーバーの権限設計の一括作成（ロール×カテゴリ）／ゲスト招待・招待コードで自動ロール／使い方ピンの書き替え／持ち主のAIから会社AIへ前提を渡す（許可リスト）／資料の索引（本棚）／週次スタンドアップ
